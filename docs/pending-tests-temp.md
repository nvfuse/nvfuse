# 남은 테스트 목록 (임시)

작성일: 2026-11-12

## 현재 검증한 범위

- macOS·Rocky Linux 9 파일 백엔드의 일반 및 ASan/UBSan 테스트
- NVFUSE → SPDK v26.09 → QEMU NVMe 경로의 데이터 비교, 생성·삭제·재마운트
- 두 랜덤 시드, 시드당 500회 덮어쓰기, 1B~64KiB의 9개 전송 크기와 여러 데이터 패턴
- 정상 종료 및 VM 재시작 후 파일 데이터·메타데이터 유지
- SPDK/NVMe 단독 다중 큐: 1/2/4개 큐 × 깊이 1/8/32/64
- NVFUSE 동작 중 읽기·쓰기 EIO, 일시 지연 후 재개, 10초 타임아웃, 장치 제거
- 비정상 종료 이미지의 재마운트 거부 및 장애 이미지 보존

장치 제거는 QEMU PCI 목록에서 실제 제거를 확인했다. 현재 NVFUSE 전송 경로는 즉시 제거 알림 대신 10초 I/O 타임아웃으로 종료된다. 자동 복구와 NVFUSE 병렬 I/O는 아직 검증되지 않았다.

## 남은 테스트

아래 순서는 우선 진행 권장 순서다. 모든 항목은 미완료 상태다.

### 1. 용량·자원 고갈

- [ ] 데이터 블록을 소진할 때 오류 반환과 부분 쓰기 처리 확인
- [ ] inode를 소진할 때 생성 실패와 기존 파일 접근 확인
- [ ] 실패 후 파일 크기, 블록 매핑, 할당 비트맵, 여유 공간·inode 카운터 일치 확인
- [ ] 삭제 후 자원 회수 및 재할당 확인
- [ ] 재마운트 후에도 일관성 유지 확인

### 2. fsync / sync 내구성

- [ ] 쓰기 후 `fsync()` 성공 시 dirty cache가 실제 장치에 제출됐는지 확인
- [ ] `sync()`의 데이터·메타데이터 제출 범위 확인
- [ ] 성공 반환 직후 정상 unmount 없이 강제 종료하고 저장 상태 검증
- [ ] 쓰기 및 flush 실패 시 성공으로 처리되지 않는지 확인
- [ ] 프로세스 종료, VM 강제 종료, 미flush 쓰기 손실 모델을 구분해 검증

현재 테스트는 `fsync()`의 성공 반환 및 정상 종료 후 데이터 유지를 검사했다. 이것만으로 강제 종료 내구성이 보장되지는 않는다. 현재 dirty inode 추적 설정과 fsync 경로의 실제 writeback 동작을 먼저 확인해야 한다. 비정상 이미지가 마운트 거부되는 경우 이를 데이터 유지 성공으로 계산하지 않는다.

### 3. 파일 연산 확대

- [ ] truncate 축소·확대, 0바이트 파일 처리
- [ ] 파일 확장과 홀 읽기의 초기화·데이터 비교
- [ ] 기존 목적지를 덮어쓰는 rename 및 실패 시 상태 확인
- [ ] 큰 디렉터리의 생성·검색·rename·삭제와 인덱스 일관성 확인
- [ ] 직접·간접 블록 경계와 지원하는 최대 파일 크기 경계 검사
- [ ] 지원 API와 오류 계약을 확인한 뒤 미지원 연산은 명시적으로 구분

### 4. NVFUSE 병렬 I/O

- [ ] 비동기 요청·버퍼 소유권·완료 처리 구조 준비
- [ ] 큐 깊이를 높이고 여러 큐·스레드에서 동시에 실행
- [ ] 서로 다른 파일 및 같은 파일의 비중첩 구간에 대한 데이터 비교
- [ ] 같은 파일의 중첩 쓰기는 정의한 동기화·순서 계약에 따라 검증
- [ ] 제출·완료 수, 요청 식별자, 중복 완료, 누락, 정리 시 미완료 요청 확인

현재 NVFUSE 통합 전송은 단일 프로세스·동기식이며 DMA bounce buffer를 공유한다. 기존 SPDK 단독 다중 큐 통과 결과를 NVFUSE 병렬 I/O 검증으로 대체하지 않는다. 구조 확장이 먼저 필요하다.

### 5. 장시간 반복·스트레스

- [ ] 생성·쓰기·읽기·rename·삭제·재마운트를 장시간 반복
- [ ] 시드와 작업 수를 늘려 실행 순서 의존 오류 검사
- [ ] 메모리, 파일 디스크립터, hugepage, 큐·풀 자원의 누적 사용량 확인
- [ ] 반복 후 데이터·메타데이터 일관성과 공간 회수 확인

### 6. 장애 후 원본 이미지 복구 — 저널링 구현 후

- [ ] 데이터·저널·commit·checkpoint·retirement의 쓰기 및 flush 경계에서 장애 주입
- [ ] 부분 쓰기, 미flush 쓰기 손실, 저장 순서 변경, flush 오류 검사
- [ ] 재포맷 없이 원본 이미지를 재개방해 복구
- [ ] 디렉터리·inode·비트맵·블록 소유권·여유 공간 카운터 일치 확인
- [ ] 완료된 commit 유지 및 미완료 메타데이터의 부분 반영 방지 확인
- [ ] 복구 중 재차 종료한 뒤 반복 복구의 동일 결과 확인
- [ ] 중단된 삭제·truncate의 자원 회수와 저널 슬롯 재사용 확인

설계 참고: [metadata-journaling-design.md](metadata-journaling-design.md).

현재의 예상된 프로세스 중단, 비정상 마운트 거부, 새 포맷 성공은 원본 이미지 복구 성공으로 계산하지 않는다.

### 7. 환경 및 장치 확대

- [ ] Linux x86_64의 NVFUSE + 실제 SPDK 통합 경로 검증
- [ ] 지원 대상에 포함한다면 Rocky Linux 8 별도 검증
- [ ] 필요 시 실제 NVMe SSD의 동작·성능 및 전원 손실 내구성 검증
- [ ] 무재부팅 장치 재연결과 재초기화 검증 — 지원 구현 후

파일 백엔드 CI, ARM64 QEMU 테스트, 실제 SSD 검증 결과를 구분한다. 실제 SSD가 없는 현재 환경에서는 물리 장치의 전원 손실 내구성을 보장하지 않는다.

## 결과 보존 원칙

- 실패 시 시드, 작업 순서, 주입 위치, write/flush 기록, 로그, 원본 이미지를 보존한다.
- 정상 재마운트, 예상된 오류 종료, 원본 복구, 재포맷 후 재사용을 별도 결과로 기록한다.
- 데이터 비교가 필요한 테스트는 일반 모드로 실행하고, 메타데이터 전용 모드는 페이로드 무결성 검증에 사용하지 않는다.
